# 電車ゲーム — アーキテクチャ

この文書は、コードと素材をどこに置き、役割をどう分けるかの現時点の方針です。[overview.md](overview.md) と [roadmap.md](roadmap.md) に従い、小さく作って必要になった時に構成を見直します。記載した将来のフォルダは、使う機能を実装する段階で追加します。

## 全体構成

スマートフォンのブラウザで動く、バックエンドのないJavaScriptアプリです。Viteがコードと素材をまとめ、Phaser 3が画面と入力を扱い、Phaser同梱のMatter.jsが落下・衝突を扱います。端末内に残すハイスコアなどは、必要になった時に `localStorage` を使用します。

```text
index.html                 ブラウザの入口。ゲーム用の要素を置く
src/
  main.js                 Phaserの起動設定とシーンの登録
  style.css               ページ全体とキャンバス周囲のスタイル
  scenes/                 スタート画面・ゲーム画面などのPhaserシーン
  game/                   画面に依存しない進化順・得点などのルールと電車データ
  assets/                 電車画像・背景・音など、Viteから読み込む素材
  storage/                ハイスコアなどの端末内保存（必要になった時）
documents/                概要、ロードマップ、構成、操作コマンド
README.md                 起動・ビルド・実機確認の手順
AGENTS.md                 このリポジトリのコードルール
```

1-1から画面の処理を `src/scenes/GameScene.js` に置き、`main.js` は起動設定を中心にします。`src/game/` 以下は、合体や進化順など、画面から独立させる必要が生じた時に追加します。

## 役割の境界

| 場所 | 担当すること |
| --- | --- |
| `src/main.js` | Phaserの画面サイズ、拡大縮小、Matterの有効化、シーン登録。ゲームのルールは置かない。 |
| `src/scenes/` | 画面の描画、タッチ入力、シーンの切り替え、Matterの物体と表示の管理。最初はゲーム画面、フェーズ2でスタート画面を追加する。 |
| `src/game/` | 11種類の識別子と素材の対応、進化順、合体・得点などのルール。車種や画像を変えても、進化順を扱う処理を直さずに済む形を目指す。 |
| `src/assets/` | 使用条件を確認した画像・音。種類ごとに整理し、コードから読み込む。 |
| `src/storage/` | `localStorage` の読み書き。保存の成否をゲームの進行から切り離す。 |
| `src/style.css` | ページの余白、背景、キャンバスの配置など。ゲーム内の絵や操作部品は原則Phaserで描く。 |

## 画面とデータの流れ

1. `index.html` が `src/main.js` を読み込み、Phaserを起動する。
2. フェーズ2以降、スタート画面で11種類の識別子を並べ替える。「ゲームスタート」でその順序の**コピー**をゲーム画面へ渡す。
3. ゲーム画面は受け取った順序をそのプレイ中の進化順として使う。落下・衝突はMatterで処理し、合体や得点の判断には `src/game/` のデータとルールを使う。
4. ハイスコアなど保存が必要になったら、`src/storage/` を経由して端末に保存する。画像は種類の識別子から対応する素材を参照する。

進化段階の番号と電車の識別子は分けます。段階はプレイヤーが決めた並び順上の位置、識別子は電車の種類そのものを表します。これにより、並べ替えや画像差し替えがゲーム内の進化処理に直接入り込まないようにします。

## 実装を進める時の扱い

- 1-1では、プレイ領域の寸法や仮の円の大きさをまとめて管理し、シーン内の複数箇所に同じ数値を散らさない。
- 画面の基準サイズと盤面の寸法は `src/scenes/gameLayout.js` に置く。盤面はスマホの横幅に近い374×453、11段階の半径は `src/game/ballStages.js` に置き、提供された面積比を参考にする。
- 画面固有の処理が増えたらシーンにまとめ、複数の画面で使うルールやデータだけを `src/game/` に移す。空の階層や将来用の抽象化は作らない。
- コードの命名、処理ブロック間の空行、日本語コメントは [AGENTS.md](../AGENTS.md) に従う。
- 完成時の公開先はGitHub Pages。配信パスなどの公開設定はフェーズ4で追加する。
