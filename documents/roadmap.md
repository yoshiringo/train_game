# 電車ゲーム — 完成までのロードマップ

この文書は [overview.md](overview.md) を実装へ進めるための作業順序です。各項目を原則として **1回の依頼で扱う単位** とし、完了条件を満たしたらチェックを入れます。仕様や数値は各作業の時点で実機確認と相談を通じて決め、決定事項を関連する文書やコードに残します。

## 完成の目安

- スマートフォンの縦画面で、電車を左右に動かして落とし、同じ段階の電車を合体させて遊べる。
- ゲーム開始前に11種類の電車を2列の一覧で自由に並べ替えられ、その順序がそのプレイ中の進化順になる。
- スコア、次の電車、ゲームオーバー、リトライ、ハイスコアが機能する。
- 11種類の電車画像と鉄道をテーマにした画面を備え、子どもが迷わず操作できる。
- スマートフォン実機で動作を確認し、GitHub Pagesの公開URLから遊べる。

## フェーズ0：開発の土台

- [x] **0-1. 開発環境と最小画面を作る** — JavaScript、Vite、Phaser 3、Matter.jsで起動する最小構成を用意する。`npm`の起動・ビルド手順をREADMEに記し、ローカルのブラウザに縦長のゲーム画面が表示される。
- [x] **0-2. 実機確認の経路を用意する** — 同じネットワーク上のスマートフォンから開発中の画面を開けるようにし、確認手順をREADMEに記す。画面幅の違いとタッチ入力を確認する。Git/GitHubの初期設定が必要なら、この段階で行う。

## フェーズ1：色付き円で遊べる試作

- [x] **1-1. プレイ領域と落下操作を作る** — 壁・床・落下位置のガイド・現在の円を表示し、指で左右に動かして離すと落下する。画面外への配置を防ぎ、スマホ縦画面で操作できる。
- [ ] **1-2. 物理挙動を整える** — Matter.jsで円同士・壁・床の衝突、重力、転がりを動かす。初期値は仮で置き、落下中に操作できない状態と次の円を出すタイミングを定める。
- [ ] **1-3. 11段階の合体を実装する** — 同じ段階の円が接触すると一度だけ合体し、次の大きさの円になる。連続合体や同時接触でも円の重複生成・消失が起きないことを確認する。最終段階同士が接触した場合の扱いは、この作業で決める。
- [ ] **1-4. ゲームの一巡を完成させる** — 落下する段階の抽選、次の円の表示、合体スコア、ゲームオーバー判定、リトライを追加する。スコアの配点、抽選対象、終了までの猶予は仮値から始め、1プレイを開始から終了まで通して遊べる。
- [ ] **1-5. 試作を実機で確認する** — スマホで落下・衝突・合体・終了まで遊び、操作しにくい箇所や明らかな不具合を修正する。この時点では色付き円のままでよい。

## フェーズ2：進化順のカスタマイズ

- [ ] **2-1. スタート画面を作る** — 11段階を示す仮アイコンを2列で並べ、順序と「ゲームスタート」ボタンを表示する。小さい画面でも全項目を確認・操作できる。
- [ ] **2-2. スマホ向けの並べ替えを実装する** — ドラッグ操作やタップ交換など、実機で使いやすい方法を選ぶ。11個を重複・欠落なく任意の順序へ並べ替えられ、現在の進化順が分かる。
- [ ] **2-3. 並び順をプレイに反映する** — 開始時の順序をそのプレイ用に確定し、出現・合体・次の円の表示へ反映する。プレイ中に順序が意図せず変わらず、リトライ時の扱いも定まっている。
- [ ] **2-4. 並べ替えを実機で確認する** — 2列表示、スクロール、タッチ操作、開始後の合体順をスマホで確認して修正する。前回の順序の保存は、実際に使って必要と判断した場合に追加する。

## フェーズ3：電車ゲームとして仕上げる

- [ ] **3-1. 11種類の電車と素材方針を決める** — 車種・初期順序・見分けやすさ・画像の利用条件を決め、各種類の識別子と素材の対応を記録する。車種や画像を後から差し替えられる形にする。
- [ ] **3-2. 電車画像を制作・組み込む** — 権利を確認した11種類の画像を用意し、円形アイコンへ組み込む。小さい段階でも判別でき、画像が読み込めない場合にも操作不能にならない。
- [ ] **3-3. 画面を鉄道テーマに整える** — スタート画面とゲーム画面に、駅・線路・標識などを使った親しみやすいデザインを適用する。スコア、ハイスコア、次の電車、操作ボタンが読みやすい。
- [ ] **3-4. 保存と演出を加える** — ハイスコアを端末内に保存する。合体や終了時の視覚演出を入れ、効果音は実機での必要性と素材の利用条件を確認して追加する。音を使う場合は消音手段を設ける。

## フェーズ4：調整・公開

- [ ] **4-1. 操作感と難易度を調整する** — 複数のスマホ画面幅で、落下位置、物理挙動、合体しやすさ、スコアとゲームオーバーまでの長さを確認して調整する。子どもが実際に遊べるなら、その観察を優先する。
- [ ] **4-2. 一通りの動作を検証する** — 並べ替えた順序での開始、連鎖合体、最高段階、ゲームオーバー、リトライ、ハイスコア保存、画面再読み込みを確認する。実行時エラーと表示崩れを解消し、本番ビルドが成功する。
- [ ] **4-3. GitHub Pagesに公開する** — 公開先のリポジトリに合わせてViteの配信パスとデプロイ方法を設定し、公開URLからスマホで起動・プレイできることを確認する。更新手順をREADMEに残す。

## 各作業で扱う未決事項

上の順序と完成条件を基準に進め、次の詳細は該当する作業の直前に決めます。

- 最終段階の合体結果、落下候補、スコア配点、ゲームオーバー判定と猶予。
- 並べ替え操作、リトライ時の進化順、前回の並び順の保存要否。
- 11種類の車種・初期順序・画像の作り方、音と演出の範囲。
- 実機で快適に遊べる物理パラメータと難易度。
